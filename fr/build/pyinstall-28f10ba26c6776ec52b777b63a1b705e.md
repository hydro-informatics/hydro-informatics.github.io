(install-python)=
# Python (Installation)

> « Le zen de projets Python florissants en 2025 est *un interprète par projet* et *une chaîne d'outils par tâche*. Master environnement virtuel d'abord; le reste suit naturellement."

Python 2 a atteint la fin de vie en **janvier 2020** et n'est plus expédié par les distributions Linux ou les installateurs Windows. Aujourd'hui, chaque paquet activement entretenu – scientifique, géospatial ou autre – supporte **CPython ≥ 3.9**, la plupart des bibliothèques testant maintenant contre **Python 3.13**. Plusieurs interprètes peuvent encore coexister sur la même machine (QGIS / ArcGIS Pro intègre ses propres 3.11, Nvidia CUDA en envoie un pour PyTorch, etc.), mais la façon moderne d'isoler les projets est de *léger* environnements virtuels créés par `venv`, **pipx**, ou *conda/mamba*.

Ce chapitre distille un flux de travail qui construit de façon fiable la pile de calcul utilisée dans ce livre électronique, quelle que soit la plateforme. Il souligne

* **`conda`/`mamba`** as a smooth cross-platofrm default solution,
* **`pip` + `venv`** for Linux/macOS (alternative; preferably use `mamba`),
* recent improvements in binary wheels for GDAL/Fiona/Shapely (pip on Windows is finally painless!), and
* sustainable ways to keep environments reproducible.

---

**Avant de continuer**, une installation python exploitable multiplateforme, incluant GDAL, peut être installée en utilisant notre [project template](https://github.com/sschwindt/python-project-template/):

1. Installez [mamba](https://mamba.readthedocs.io) pour votre plateforme.
2. Téléchargez notre [environment.yml](https://github.com/sschwindt/python-project-template/blob/main/environment.yml).
3. Ouvrez un terminal (command promptline), naviguez jusqu'au répertoire où l'environnement * téléchargé. yml* vit et crée l'environnement :
   ```bash
   mamba env create -f environment.yml
   ```
4. Activer l'environnement et exécuter Python:
   ```bash
   mamba activate wrr-proj
   (wrr-proj) user@computer:$ python
   ```
5. Vérifiez si l'installation des géopackages a fonctionné (aucun message d'erreur ne doit se produire):
   ```bash
   >>> from osgeo import gdal
   ```

6. Optionnellement, si la vérification a réussi, quitter python et pip-install flusstools dans cet environnement `wrr-project`:
   ```bash
   >>> exit()
   (wrr-proj) user@computer:$ pip install flusstools
   ```

(pip-env)=
## `pip` + `venv` 

```{admonition} The advantage of virtual environments over system‑wide Python installations
:class: tip
L'interpréteur *system* pilote les outils de bureau de base ; le changer peut briser votre système d'exploitation. A `venv` vit entièrement dans votre répertoire personnel, pèse <50 Mo, et disparaît avec un seul `rm -rf`. De plus, le système d'exploitation plus récent, comme Linux Mint 22.1 ou plus jeune, ne laisse pas un utilisateur `pip` installer quoi que ce soit dans l'environnement python à l'échelle du système.
```


(pip-quick)=
### Démarrage rapide (Linux Mint/Ubuntu 22.04 LTS ou ultérieur)

#### Installer un nouvel interprète
```
$ sudo apt update && sudo apt install python3 python3-venv python3-dev build-essential libgdal-dev gdal-bin
```

Les dépôts Debian/Ubuntu modernes paquetent déjà CPython 3. Les en-têtes *dev* supplémentaires sont nécessaires pour les roues qui compilent encore des extensions C au moment de l'installation.

#### Créer & activer un environnement

```bash
$ python3 -m venv ~/venvs/vflussenv
$ source ~/venvs/vflussenv/bin/activate
```

A `venv` n'hérite que du binaire de l'interprète.


#### Mise à niveau des outils de base

```bash
(vflussenv) $ python -m pip install --upgrade pip wheel setuptools
```

`pip 24.x` regroupe la nouvelle fonction *repair wheel* qui corrige plusieurs roues-linux et macOS à la volée.


#### Installer les exigences

Pour l'analyse des données [sans la bibliothèque géospatiale GDAL, téléchargez ce fichier requirements.txt](https://github.com/sschwindt/sample-data/blob/main/python-env/requirements.txt). Autrement, pour [inclure les bibliothèques pour l'analyse des données géospatiales, télécharger ce requirements.txt](https://github.com/Ecohydraulics/flusstools-pckg/raw/refs/heads/main/requirements.txt). Installez le fichier requirements.txt dans un nouvel environnement appelé `vflussenv' comme suit.

```bash
(vflussenv) $ pip install -r requirements.txt
```

Des roues binaires pour GDAL, Rasterio, Fiona et Shapely sont disponibles sur PyPI depuis **2024‐10**, donc plus de PPA externe n'est nécessaire.

```{admonition} python vs. python3
:class: note
Toutes les distributions principales pointent maintenant le `python` symlink vers Python3. Si `python --version` imprime encore *Python 2.x* vous êtes sur un système obsolète; toujours appeler le plein `python3` binaire à la place.
```

#### Installer les flusstools


```bash
(vflussenv) $ pip install flusstools
```

Essaie-le.

```bash
(vflussenv) $ python
>>> import flusstools as ft
```

### État 2025 de GDAL sous Windows

* 2024‐10: **gdal‐3.9.0‐cp311‐win amd64.whl** atterrit sur PyPI > pure‐`pip` installs enfin fonctionne sur Windows.
* Cependant, les grandes piles géospatiales (Proj, GEOS, HDF5, NetCDF) sont encore plus faciles via le canal **conda-forge**.
* Utiliser `pip` seulement lorsque vous *doivez garder l'environnement minimal.

## Environnements de mise à jour

### Mettre à jour l'environnement virtuel (venv)

agréable—virtualenv rend cela simple. ici, c'est un flux de mise à niveau **robust en place** qui maintient votre veine actuelle (`vflussenv`) et se concentre sur **JupyterLab** + **Jupyter Book**.

**1. Activer & instantané pour faciliter le retour**

```bash
# activate your venv if not already
source vflussenv/bin/activate

# snapshot current state for rollback
pip freeze > requirements-$(date +%Y%m%d).txt
```

**2. Assurez-vous que la chaîne d'outils de construction est à jour**

```bash
pip install -U pip setuptools wheel
```

**3. Aperçu des paquets périmés**

```bash
pip list --outdated
```

**4. Mettre à jour tous les paquets (deux options)**

`````{tab-set}
````{tab-item} Option A -- safe loop (exhaustive)

Mettre à jour chaque paquet *pip-managed* sauf les installations VCS/URL directes.

```bash
python - <<'PY'
```

```python
import json, subprocess, sys
# get outdated packages in JSON
out = subprocess.check_output(
    [sys.executable, "-m", "pip", "list", "--outdated", "--format=json"],
    text=True
)
# take just the package names
names = [pkg["name"] for pkg in json.loads(out)]

# optional: don't re-upgrade the bootstrap tools every loop
skip = {"pip", "setuptools", "wheel"}
for name in names:
    if name in skip:
        continue
    subprocess.check_call([sys.executable, "-m", "pip", "install", "--upgrade", name])
PY
```

````

````{tab-item} Option B -- "requirements with >="

Cette option préserve une sauvegarde et gère les différences macOS/Linux `sed`.

```bash
# start from a clean freeze
pip freeze > requirements.txt

# Linux:
sed -i 's/==/>=/' requirements.txt
# macOS (BSD sed):
# sed -i '' 's/==/>=/' requirements.txt

# upgrade per the relaxed pins
pip install --upgrade -r requirements.txt

````
`````


**5. En option, épinglez le nouvel ensemble**

```bash
pip freeze > requirements-upgraded-$(date +%Y%m%d).txt
```

**6. Vérifier**

```bash
jupyter lab --version
jupyter-book --version
python -c "import sys; print(sys.version)"
```

**7. Nettoyage**

Nettoyer les vieux caches de construction pour économiser de l'espace disque :

```bash
pip cache purge
```


````{admonition} Conflicts / "ResolutionImpossible"
:class: note

* Commencez par mettre à niveau les **racines** (par exemple, `pip install -U jupyterlab jupyter-book nbclient nbconvert`) et réessayer.
* Si l'erreur désigne une pin spécifique dans votre `requirements.txt`, détendez-vous ** juste celui** (ou supprimez la ligne) et recourez.
* Si vous mélangez éditable/VCS installe, mettez-les à niveau individuellement : `pip install -U git+https://...`.
* Le pire cas : retournez à votre instantané :

  ```bash
  pip install -r requirements-YYYYMMDD.txt
  ```
````


### Mettre à jour conda env

```{admonition} Conda vs. mamba
:class: note

Si vous utilisez `mamba`, préférez les commandes `mamba` -- ce sont *drop-in*.
```

**1. Créer un instantané de l'état actuel (repli facile)**

```bash
# exact conda specs
conda list --explicit > conda-specs-$(date +%Y%m%d).txt
# pip packages (if any were installed via pip)
python -m pip freeze > pip-freeze-$(date +%Y%m%d).txt
```

**2. Facultatif mais recommandé: conservez votre version mineure actuelle de Python**

Cela empêche un saut inattendu de Python qui peut causer des conflits. Ajuster `3.11.*` à quelque `python --version` montre :

```bash
python --version
# pin to current minor while updating other deps
conda install "python=3.11.*" -c conda-forge
```

**3. Assurez-vous que votre solveur est à jour**

```bash
# update conda itself (and mamba if you have it) in base
conda activate base
conda update -n base -c conda-forge conda
# optional: if you use mamba
conda install -n base -c conda-forge mamba
conda activate vflussenv
```

**4. Mettre à jour tous les paquets conda**

Utilisez la conda-forge stricte pour la cohérence (pour ne pas modifier votre YAML).

```bash
# with mamba (faster)
mamba update --all -c conda-forge --yes

# or with conda
conda update --all -c conda-forge --yes
```

**5. Si vous avez utilisé *pip* pour certains paquets, mettez à jour ceux aussi**

Seulement faire cela **après** la mise à jour de conda. Cela maintient conda en charge des bibliothèques centrales.

```bash
# show what’s outdated (pip-managed only)
python -m pip list --outdated

# upgrade all pip-managed packages (safer loop than xargs)
python - <<'PY'
import subprocess, sys
out = subprocess.check_output([sys.executable, "-m", "pip", "list", "--outdated", "--format=freeze"], text=True)
pkgs = [line.split("==")[0] for line in out.splitlines() if "@" not in line]
for p in pkgs:
    subprocess.check_call([sys.executable, "-m", "pip", "install", "-U", p])
PY
```

**6. Caches propres**

```bash
conda clean -a -y
```

**7. Vérifier les versions**

```bash
jupyter lab --version
jupyter-book --version
python -c "import sys, jupyterlab; print('py', sys.version);"
```

```{admonition} If the solver struggled...
:class: tip

* Essayez d'abord une mise à jour ciblée pour les grandes bibliothèques (par exemple, `mamba update pandas numpy scipy -c conda-forge`), puis `--all`.
* Si vous avez vraiment besoin de mettre à niveau Python, faites-le explicitement (par exemple, `conda install python=3.12.* -c conda-forge`) puis `update --all`.
* Si vous mélangez fortement pip/conda et obtenez des conflits, envisagez de garder la pile scientifique (NumPy/SciPy/PyTorch/etc.) sur conda-forge et applications/utilités via pip.

```

(install-python-summary)=
## Résultat de l'installation

* Utilisez **`python -m venv`** (`pipx` pour les outils CLI) à moins qu'un paquet *requiert* les bibliothèques C/C++ que votre OS ne peut satisfaire - puis atteindre **conda-forge**.
* Les utilisateurs de Windows ne sont plus *besoin* conda pour GDAL, mais conda reste le chemin le plus facile pour une pile de données géospatiales.
* Épinglez les versions exactes pour les projets d'archives; utilisez `>=` pins pour le code de recherche vivant.
* N'installez jamais de paquets avec `sudo pip`; travaillez toujours dans un environnement isolé.
