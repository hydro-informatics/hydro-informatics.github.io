# Virtuelle Maschinen und Linux

Ihr Computer ist einer Ihrer wichtigsten Bildungsbegleiter. Sie möchten also die Gesundheit Ihres Computers schützen und Probleme vermeiden, die durch redundante oder sogar bösartige Software verursacht werden. Aus diesem Grund wird empfohlen, alle auf dieser Website verwendeten Software auf einer sogenannten Virtual Machine (VM) zu installieren. Diese Seite erklärt, was VMs sind, welche Vorteile sie genau haben und wie Sie [Debian Linux](https://www.debian.org/), eines der stabilsten und sichersten Betriebssysteme] installieren können. Es spielt keine Rolle, ob Sie Apples *mac OS * oder Microsofts *Windows * verwenden oder ob Sie bereits Linux verwenden: Die VM sieht am Ende gleich aus.


## Über

### Was ist eine virtuelle Maschine (VM)?

Eine virtuelle Maschine (VM) stellt ein virtuelles Betriebssystem (OS) dar, das auf einem Hostsystem ausgeführt wird, das direkt auf einem physischen Computer ausgeführt wird. Die physischen Computer- (Hardware-)Ressourcen des Host-Systems werden über sogenannte Hypervisoren vergeben. Aus diesem Grund wird die virtuelle Maschine als *Gastmaschine * und der Hypervisor als *Hostmaschine * bezeichnet. Eine *Gastmaschine* ist also eine isolierte, virtualisierte Umgebung, die unabhängig auf dem Host-Betriebssystem läuft.

### Warum eine VM verwenden?

Kostenlose Ressourcen auf einem Computer stellen aus wirtschaftlicher Sicht toten Speicherplatz dar, der Kosten verursacht, ohne Einnahmen zu generieren. Aus diesem Grund erstellen Systemadministratoren häufig mehrere virtuelle Server, um physische Ressourcen besser zuzuweisen und Energie zu sparen. Eine VM ist auch für intelligente Endnutzer wie Forscher und Ingenieure nützlich. Hier sind einige Vorteile einer VM:

* Anwendungen und Dienste mehrerer VMs stören sich nicht gegenseitig.
* Unabhängigkeit des Gastsystems vom Betriebssystem des Hostsystems und der physischen Hardware.
* VMs können verschoben oder geklont werden, indem sie einfach auf andere Systeme kopiert werden.
* Hardware-Ressourcen können dynamisch über den Host-Hypervisor zugewiesen werden.
* Bessere und effizientere Nutzung vorhandener Hardwareressourcen.
* Kurze Bereitstellungszeiten für Systeme und Anwendungen, die auf einer VM laufen.
* VMs bieten hohe Verfügbarkeit und Flexibilität aufgrund ihrer Unabhängigkeit von physischen Ressourcen.


Im Rahmen der Hydroinformatik für das Wasserressourcenmanagement kann eine VM dazu dienen, verschiedene * Python * Skripte mit unterschiedlichen Abhängigkeiten auszuführen oder vor allem eine saubere und effiziente Umgebung für die Ausführung numerischer Modelle wie [open TELEMAC-MASCARET](http://www.opentelemac.org/)] einzurichten.

This tutorial provides guidance on {ref}`creating a new VM <vm-create>`, {ref}`re-using an existing VM <hyfo-vm>`, and {ref}`working with Debian Linux on a VM <debian>`.

  + *Version:* Debian (64-bit) <br>> Klicken Sie auf den Button *Next*

## Wiederverwendung (Export/Transfer oder Kopieren) einer VM auf einem anderen Host

Once you have created a VM on a virtual hard disk (the `*.vdi` file), you can always transfer it to another *host* system with its ecosystem. To copy (or transport) the VM:

* Auf dem ursprünglichen Host:
  * Schließen Sie die VM, die Sie wiederverwenden möchten.
  * Gehen Sie in VirtualBox zu **File** > **Export Appliance...**.
  * Follow the instructions to export the VM to a `*.ova` file (the **export process may take 10-15 minutes**).
* Auf dem neuen Host:
  * Stellen Sie sicher, dass VirtualBox installiert ist.
  * Kopieren Sie die exportierte `*.ova`-Datei in das neue Hostsystem.
  * Öffnen Sie VirtualBox und gehen Sie zu **File** > **Import Appliance...**
  * Navigieren Sie zu dem Verzeichnis, in dem Sie die `*.ova`-Datei kopiert haben.
  * Klicken Sie auf **Weiter**.
  * Überprüfen Sie die **Appliance-Einstellungen ** und klicken Sie auf **Import **.

Nun sollte die virtuelle Maschine in der Liste der virtuellen Maschinen in VirtualBox sichtbar sein.

(hyfo-vm)=
## Importieren einer vorhandenen VM in Oracle VM VirtualBox

Anstatt eine neue VM von Grund auf neu zu erstellen, können Sie eine bestehende VM in Oracle VM VirtualBox importieren. Dies ist nützlich, wenn eine VM bereits mit dem erforderlichen Betriebssystem, der Software, den Einstellungen und der Benutzerumgebung konfiguriert wurde.

Bestehende VMs werden üblicherweise in einem der folgenden Formate bereitgestellt:

* eine Appliance-Datei, typischerweise `.ova` oder `.ovf`
* ein virtuelles Festplattenabbild, wie `.vdi`, `.vmdk` oder `.vhd`

Das Importverfahren hängt vom Dateityp ab.

### Importieren einer VM Appliance

Make sure that Oracle VM VirtualBox is installed, as described in {ref}`the VM requirements <vm-requirements>`. Then open VirtualBox and:

* Gehen Sie zu **File** > **Import Appliance...**
* Wählen Sie die Datei `.ova` oder `.ovf` aus.
* Klicken Sie auf **Weiter**.
* Überprüfen Sie die Geräteeinstellungen, einschließlich:
  * VM-Name
  * Basisordner
  * CPU-Zuweisung
  * RAM-Zuweisung
  * Einstellungen für Netzwerkadapter
  * Ort der virtuellen Festplatte
* Passen Sie die Einstellungen bei Bedarf an.
* Klicken Sie auf **Finish** oder **Import**.

Nach dem Import sollte die VM in der Liste der verfügbaren VMs in VirtualBox erscheinen.

### Registrieren einer vorhandenen virtuellen Festplatte

Wenn die VM als virtuelles Festplattenimage und nicht als Appliance bereitgestellt wird, erstellen Sie eine neue VM und fügen Sie die vorhandene Festplatte an:

* Klicken Sie auf **New** in VirtualBox.
* Geben Sie einen VM-Namen ein.
* Wählen Sie den entsprechenden OS-Typ und die entsprechende Version aus.
* Zuweisung von RAM- und CPU-Ressourcen.
* Wenn Sie zu einer Festplatte aufgefordert werden, wählen Sie **Verwenden Sie eine vorhandene virtuelle Festplatte **.
* Wählen Sie die Datei `.vdi`, `.vmdk` oder `.vhd`.
* Beenden Sie das VM-Setup.

Bevor Sie die VM starten, überprüfen Sie die VM-Einstellungen und passen Sie sie bei Bedarf an.

### Starten und Konfigurieren der importierten VM

Nach dem Importieren oder Registrieren der VM starten Sie sie im Hauptfenster der VirtualBox. Überprüfen Sie beim ersten Start die folgenden Elemente:

* **Keyboard Layout**: Stellen Sie sicher, dass das Gastbetriebssystem das erwartete Tastaturlayout verwendet.
* **Anmeldeinformationen**: Verwenden Sie die mit der VM-Dokumentation bereitgestellten Anmeldeinformationen.
* **Netzzugang**: Überprüfen Sie, ob die VM NAT, Bridged Networking oder einen anderen Netzwerkmodus verwendet.
* **Anzeigeeinstellungen**: Einstellen der Bildschirmauflösung und -skalierung, falls erforderlich.
* **Gastzusätze **: Installieren oder aktualisieren Sie VirtualBox Guest Additions, wenn freigegebene Zwischenablage, dynamische Größenänderung oder Ordnerfreigabe nicht funktionieren.
* **System-Updates**: Wenn das Gastbetriebssystem Paketupdates unterstützt, aktualisieren Sie es, bevor Sie zusätzliche Software installieren.
* **Shared folders**: To exchange files between the host and guest systems, configure shared folders as described in {ref}`folder sharing <vm-share>`.

Für Linux-Gäste können Systemupdates in der Regel vom grafischen Update-Manager oder vom Terminal aus gestartet werden. Verwenden Sie für Debian- oder Ubuntu-basierte Systeme:

```bash
sudo apt update
sudo apt full-upgrade
sudo apt autoremove
```

### Empfohlene VM-Einstellungen

Bevor Sie die VM für größere Berechnungen oder Softwareinstallationen verwenden, überprüfen Sie die folgenden Einstellungen:

* **RAM**: Weisen Sie genügend Speicher für das Gastbetriebssystem und die Gastanwendungen zu, lassen Sie jedoch ausreichend RAM für das Hostsystem.
* **CPU**: Weisen Sie mehrere CPU-Kerne nur zu, wenn das Hostsystem über genügend Ressourcen verfügt.
* **Speicherung **: Stellen Sie sicher, dass die virtuelle Festplatte genügend freien Speicherplatz hat.
* **Netzwerk**: Verwenden Sie NAT für einfachen Internetzugang oder überbrückte Netzwerke, wenn die VM im lokalen Netzwerk sichtbar sein muss.
* **Schnappschüsse**: Erstellen Sie einen Snapshot vor größeren Updates oder Konfigurationsänderungen.

Mit einem Snapshot können Sie zu einem früheren VM-Status zurückkehren, wenn ein Aktualisierungs-, Installations- oder Konfigurationsschritt fehlschlägt.

## Setup Linux

***Geschätzte Dauer: 15 Minuten.***

Starten Sie die *Debian Linux * VM aus dem *VirtualBox * Managerfenster. Sobald Debian Linux gestartet ist, melden Sie sich mit Ihren Benutzerinformationen an.

Um die volle Funktionalität des Systems zu aktivieren, öffnen Sie das Linux-Terminal (`CTRL` + `Alt` + `T`) oder gehen Sie zu *Aktivitäten* > *Akten* (Archivsymbol), klicken Sie mit der rechten Maustaste auf einen beliebigen Ordner und wählen Sie *Im Terminal öffnen*. In *Terminal* Typ:

```
su
```

Geben Sie das oben erstellte Passwort für den Root-Benutzernamen ein (siehe Abschnitt Installation).

```{note}
Root access (e.g., for installing software) is granted on many Linux distributions using the `sudo` command before the command to execute. In Debian Linux, `sudo` may refer to the wrong account and not work as desired. As a workaround type `su` in *Terminal*. Read more later in this section.
```

Installieren Sie alle Pakete, die zum Erstellen von Kernelmodulen erforderlich sind:

```
apt update
apt install build-essential dkms linux-headers-$(uname -r)
```

Suchen Sie das Dropdown-Menü *Geräte* des Fensters *VirtualBox VM* (nicht in Debian Linux selbst) und wählen Sie das CD-Image *Insert Guest Additions...* (je nach Version von *VirtualBox* kann sich dieses Menü oben oder unten im Fenster befinden).

```{admonition} Where is the **Devices** entry?
:class: tip
Das Fenster *VirtualBox VM* zeigt das Menü mit dem Eintrag *Geräte* nirgendwo an?

* Dies kann passieren, wenn *View* auf *Scaled mode* gesetzt wurde.
* Um den Ansichtsmodus umzuschalten und die Menüleiste sichtbar zu machen, drücken Sie die RIGHT `CTRL` (`Host`) Taste + die `C` auf Ihrer Tastatur, während Sie sich in der Hostsystemansicht befinden.
```

```{admonition} If the error **The guest system has no CR-ROM ...** occurs...
:class: warning
To troubleshoot the error message `The guest system has no CR-ROM ...`, shut down the VM. In the *VirtualBox* manager window, right-click on the *Debian Linux* VM > *Storage* tab > Add new Optical Drive to *Controller: IDE*. Restart the *Debian Linux* VM.
```

Zurück im Debian Linux *Terminal * mounten Sie die *Guest Additions * *iso * Datei, indem Sie *Terminal * eingeben:

```
sudo mkdir -p /mnt/cdrom
sudo mount /dev/cdrom /mnt/cdrom
```

Navigieren Sie zum eingebundenen Verzeichnis und führen Sie die Datei *VBoxLinuxAdditions.run* mit dem Flag *--nox11* aus, um ein Xterm-Fenster zu vermeiden.

```
cd /mnt/cdrom
sudo sh ./VBoxLinuxAdditions.run --nox11
```

Die Kernel-Module werden jetzt installiert und *Terminal* sollte eine Nachricht auslösen, die Sie zum Neustart des Systems auffordert. Dies geschieht durch Eingabe:

```
shutdown -r now
```

Stellen Sie nach dem Neustart sicher, dass die Installation erfolgreich war. In *Terminal* Typ:

```
lsmod | grep vboxguest
```

The installation was successful if the *Terminal*'s answer is something like `vboxguest   358395 2 vboxsf`. Read more about *Guest Additions* on the [*VirtualBox* developer's website](https://www.virtualbox.org/manual/ch04.html).

Um das visuelle Erlebnis zu verbessern, tun Sie Folgendes:
* Klicken Sie in der oberen linken Ecke des Debian Linux Desktops auf *Aktivitäten * und geben Sie im Suchfeld *Anzeigen * ein.
* Öffnen Sie die Einstellungen *Displays*, um eine bequeme Anzeigeauflösung auszuwählen.
  * Wenn Sie eine zu hohe Auflösung wählen, wird das Fenster *VirtualBox VM * schwarz und springt nach 15-30 Sekunden wieder auf die ursprüngliche Auflösung zurück.
  * Erwägen Sie auch, * Night Light * einzuschalten, um Ihr Augenlicht zu erhalten.
* *Anwenden* der Änderungen und Schließen der *Displays*-Einstellungen.

## Nutzerrechte
When installing software later, it is good practice to install it for your user account and not for `root`. Such system-relevant actions require *superuser* (`su`) rights. However, your default user name is not on the so-called *sudoers* list, which is essentially a file where all user accounts are listed that are authorized to use `sudo` in front of any command. So add your user account to the *su-doers* list by opening *Terminal* and typing:

```
su
    password: ...
sudo usermod -aG sudo YOUR-USER-NAME
```

Öffnen Sie eine neue Registerkarte *Terminal* (`Shift` + `CTRL` + `T`), die sich in Ihrem Standardbenutzerbereich mit Standardbenutzerrechten öffnen sollte. Überprüfen Sie, ob Ihr Konto auf der * Sudoers * Liste steht, indem Sie eingeben:

### Pakete finden

Some software will run into errors because of missing library files (e.g., `libGLX.so.0: No such file or directory`). To find out what package needs to be installed for getting the missing library file, install *apt-file*

To find out the package name of a missing library file (e.g., `libGLX.so.0`), tap:

Nach ein paar Sekunden der Suche wird *apt-file * etwas wie:


`````{tab-set}
**Wo sind die Proton-Dateien und speichert?**

Proton erstellt pro Spiel ein Windows-ähnliches Präfix.

1. APT Dampfpfade:
   * Protonenpräfixe:

`.../pfx/drive_c/`
   * Custom Proton installiert (Proton-GE):
`~/.steam/steam/compatibilitytools.d/`

2. Flatpak Dampfpfade:
   * Base Steam Dir:
`~/.var/app/com.valvesoftware.Steam/.local/share/Steam/`
   * Präfixe:
`.../steamapps/compatdata/<APPID>/pfx/`
   * Custom Proton installiert:
`.../compatibilitytools.d/`

3. Verwaltung von Präfixen:

**Schnelle Fehlersuche Playbook:**

1. Das Spiel startet nach einem Update nicht:

   * Überprüfen Sie Spieldateien.
   * Delete the `compatdata/<APPID>` prefix and relaunch.

2. Schwarzer Bildschirm mit Audio:

````{tab-item} Wine (Direct Installation)
Die oben beschriebene Installation von Debian Linux erstellt eine 64-Bit-VM und um die Programmkompatibilität mit 32-Bit-Architekturen zu ermöglichen, fügen Sie 32-Bit-Architekturen über *Terminal* hinzu:

```
sudo dpkg --add-architecture i386 && sudo apt update
```

Installieren Sie dann *Wine* mit:

```
sudo apt install wine wine32 wine64 libwine libwine:i386 fonts-wine
```


Überprüfen oder konfigurieren Sie nach der Installation von *Wine* Ordnerlinks und Kompatibilitätsumgebungen, indem Sie `wine winecfg` eingeben, wodurch das Fenster *Wine-Konfiguration* geöffnet wird, wobei:

* Ordner-Links sind in der Registerkarte *Desktop Integration * definiert.
* Die Registerkarte *Anwendungen* ermöglicht es, die zu verwendende *Windows*-Kompatibilitätsschicht zu definieren (z. B. * Windows 10*) und Anwendungen festzulegen.

So installieren Sie eine *Windows*-Anwendung:

1. Laden Sie das Installationsprogramm herunter (z. B. eine *exe*- oder *msi*-Datei).
1. Öffnen Sie *Terminal* und geben Sie `wine control` > Ein *Windows*-ähnliches Fenster öffnet sich ([lesen Sie mehr](https://wiki.winehq.org/Control)].
1. Klicken Sie in diesem Fenster auf die Schaltfläche *Add/Remove...*, die ein anderes Fenster öffnet (*Add/Remove Programme*).
1. Klicken Sie auf die Schaltfläche *Installieren...* und wählen Sie das heruntergeladene *exe* oder *msi* Installationsprogramm aus.
   * Befolgen Sie die Installationsanweisungen (Standard *Windows *-Prozedur).
   * Consider to add a *Desktop Icon*, or note the installation directory (e.g., `"C:\\Program Files (x86)\\CHC\\BlueKenue\\"`).
   * In the background. *Terminal* might prompt the message `err:mscoree:LoadLibraryShim error reading registry key for installroot` - you may ignore such messages ([read more](https://forum.winehq.org/viewtopic.php?t=14618)).

```{admonition} Never run wine as root (sudo).
:class: error, dropdown
Why? It is just not safe. So if you did run wine as root anyway, roll back with `cd $HOME` and tap `sudo chown -R $USER:$USER .wine`
More information is available in the [wine docs](https://wiki.winehq.org/FAQ#Should_I_run_Wine_as_root.3F).
```

** Starten Sie eine *Windows*-Anwendung**, indem Sie `wine explorer` in *Terminal* eingeben. *Wine*s *Windows*-Dateisystem wird in einem *Windows*-ähnlichen Fenster angezeigt. Zum Start und zur Anwendung:

* Wenn während der Installation ein *Desktop-Icon* erstellt wurde, gehen Sie zu *Desktop* und doppelklicken Sie auf die Anwendung (z. B. *BlueKenue*).
* Andernfalls identifizieren Sie den Installationspfad und die ausführbare Datei, die die Anwendung startet.
   * 32-bit programs are typically installed in `"C:\\Program Files (x86)\\` (e.g., `"C:\\Program Files (x86)\\CHC\\BlueKenue\\BlueKenue.exe"`).
   * 64-bit programs are typically installed in `"C:\\Program Files\\`.
* Mit dem Installationspfad kann jede *Windows*-Anwendung über *Terminal* gestartet werden mit:
   * `wine "C:\\path\\to\\the.exe"` (verwenden Sie `\\`, um Unterverzeichnisse zu trennen).
   * For example, `wine "C:\\Program Files (x86)\\CHC\\BlueKenue\\BlueKenue.exe"` typically starts *Blue Kenue<sup>TM</sup>*.
`````
