# hydro-informatics.com — source

This repository is the **source** for [hydro-informatics.com](https://hydro-informatics.com), built with **Jupyter Book 2** (MyST).

**Important:** Installation instructions are valid and tested on Debian Linux - based operating systems only!

## Repositories

| Repo | Purpose |
|------|---------|
| `hydro-informatics/home` *(this repo, private)* | Source files: Markdown, notebooks, config |
| `hydro-informatics/hydro-informatics.github.io` `gh-pages` branch | Deployed static site — what the browser sees |
| `hydro-informatics/jupyter-python-course` `main` branch | Standalone notebooks for Binder launch buttons |

Clone the **source** repo:

```bash
# SSH (preferred)
git clone git@github.com:hydro-informatics/home.git
# HTTPS
git clone https://github.com/hydro-informatics/home.git
```

Clone the **deploy** repo (gh-pages branch only):

```bash
git clone --single-branch --branch gh-pages \
  git@github.com:hydro-informatics/hydro-informatics.github.io.git
```

## Install the environment

Use **mamba** with the repo-local `environment.yml`. This installs Python, Jupyter Book 2, and Node.js together.

```bash
mamba env create -f environment.yml   # first time
mamba activate hywebv2
```

To update an existing environment:

```bash
mamba env update -n hywebv2 -f environment.yml --prune
```

Verify the toolchain:

```bash
python --version          # should be 3.13.x
jupyter-book --version    # should be 2.x
node --version            # should be 22.x or newer
```

## Build the eBook

All commands run inside the `hywebv2` environment.

| Goal | Command |
|------|---------|
| Live preview with hot reload | `mamba run -n hywebv2 jupyter-book start` |
| Headless build (no browser) | `mamba run -n hywebv2 jupyter-book start --headless` |
| Static HTML for deployment | `NODE_NO_WARNINGS=1 mamba run -n hywebv2 jupyter-book build --html` |
| With notebook execution | add `--execute` to any of the above |

> `NODE_NO_WARNINGS=1` suppresses a `[DEP0169]` deprecation warning emitted by the bundled mystmd JavaScript on Node 22+. It originates in the library code, not in the source files of this book.

The static build output lands in `_build/html/`.

## Deploy to hydro-informatics.com

Use the `deploy.sh` script in this directory:

```bash
bash deploy.sh          # build + sync to gh-pages repo, then review manually
bash deploy.sh --push   # build + sync + commit + push in one step
```

The script:
1. Runs `jupyter-book build --html`
2. Checks that the sitemap does not contain `localhost`
3. Uses `rsync --delete` to mirror `_build/html/` into the `hydro-informatics.github.io` repo, preserving `CNAME`, `.nojekyll`, and the Google site-verification file
4. Stages all changes; optionally commits and pushes with `--push`

> **After merging others' changes**, always re-run the build before deploying so you do not overwrite newer content.

### Manual deploy (without the script)

```bash
# 1. Build
NODE_NO_WARNINGS=1 mamba run -n hywebv2 jupyter-book build --html

# 2. Sync
rsync -av --delete \
  --exclude=".git" --exclude="CNAME" --exclude=".nojekyll" --exclude="google*.html" \
  _build/html/ /home/schwindt/github/hydro-informatics.github.io/

# 3. Ensure .nojekyll exists (prevents GitHub from mangling JSON/JS files)
touch /home/schwindt/github/hydro-informatics.github.io/.nojekyll

# 4. Commit and push
cd /home/schwindt/github/hydro-informatics.github.io
git add -A
git commit -m "Deploy hydro-informatics.com — $(date -u '+%Y-%m-%d %H:%M UTC')"
git push origin gh-pages
```

## Editing content

### Internal cross-references

Use MyST `{ref}` for all internal links — **not** bare Markdown `[text](#anchor)`. Use normal `[text](url)` for external links only.

```md
{ref}`section-label`          ← section reference
{numref}`Figure %s <fig-id>`  ← numbered figure reference
{term}`Froude number`         ← glossary term
{cite:t}`key_year`            ← inline citation  (Author, Year)
{cite:p}`key_year`            ← parenthetical citation  (Author, Year)
```

### Citations

The bibliography lives in `references.bib`. Export a BibTeX entry from Zotero (Better BibTeX → *Export Item…*) and paste it at the bottom of `references.bib`:

```bibtex
@misc{flussteam_tools_2026,
  title = {{{FlussTools}}},
  author = {Schwindt, Sebastian and Negreiros, Beatriz and Barros, Ricardo
            and Henning, Niklas and Mouris, Kilian},
  year = {2023},
  doi = {10.17605/OSF.IO/G7K52},
  howpublished = {GitHub \& Center for Open Science (OSF)}
}
```

The full Zotero group library is at <https://www.zotero.org/groups/4917569/hydro-informatics>.
The rendered references page is `documentation/bibliography.md`.

### Glossary

Add new terms to `documentation/glossary.md` inside the `` `````{glossary} `` block. Each definition line needs **two-space** indentation. Reference terms anywhere with:

```md
{term}`Anabranch`
```

### Jupyter notebooks

The book has two parallel notebook workflows:

- **Website notebooks** live in `jupyter/` — they use `{ref}` cross-references and are built into the site.
- **Standalone notebooks** live in `hydro-informatics/jupyter-python-course` — stripped of site-specific syntax so users can launch them on Binder. The `binder/environment.yml` in that repo defines the Binder runtime.

### Images and files

- Store images in `img/<section>/` (e.g., `img/openfoam/`).
- Keep file sizes below **800 KB**. Use JPG for photos, PNG (with alpha) for diagrams.
- Large tutorial files (> 500 MB) go in a dedicated repository; link to them from the relevant content page.

### Repeated links (substitutions)

The old `{{ variable }}` substitution syntax from JB 1 is **not supported** by Jupyter Book 2.1. All former substitution tokens (`{{ ft_url }}`, `{{ tm2d }}`, `{{ scolari }}`, etc.) have been inlined as plain Markdown links directly in the source files. When you add a link that will appear many times, just write it out each time (or use a footnote-style reference if Markdown supports it for your use case).

### Style baseline

- Refer to this project as *eBook* (not "website" or "book").
- Use sentence case for all section headers.
- Follow [PEP 8](https://pep8.org/) for Python code.
- Prefer scientific references with DOI links for factual statements.
- Define new technical terms in the glossary before using them.
- Keep top-level `_toc.yml` entries sparse — the eBook is already large.
- Run a spell-checker before publishing a new page.
